# Esca Linux インストーラー

Arch Linux をベースに、**日本語環境まで含めて動く状態**を対話形式で構築するインストーラーです。
パーティション作成からデスクトップ環境の設定、日本語入力、テーマの適用までを一本のスクリプトで行います。

Esca はチョウチンアンコウの発光する疑似餌のことです。深海で道を照らす光、という含意でこの名前にしています。

---

## 特徴

- **日本語環境が初めから整っている** — ロケール・タイムゾーン・JIS キーボード・fcitx5-mozc・CJK フォントを既定で構成します。インストール直後から日本語が打てて、文字化け（豆腐）も起きません。
- **8 種類のデスクトップ環境に対応** — GNOME / KDE / Xfce / Budgie / COSMIC / Hyprland / Niri / CLI のみ。DE ごとに必要なパッケージとディスプレイマネージャーの組み合わせを検証済みです。
- **設定の引き継ぎ** — 今使っているマシンの `~/.config` か、GitHub 上の dotfiles リポジトリから設定を持ち込めます。新しいマシンでも見た目と操作感をそのまま再現できます。
- **ドライラン** — ディスクに一切触れずに、生成される設定ファイルだけを確認できます。
- **失敗したときに理由が分かる** — どのコマンドが何行目で落ちたかを表示し、全ログをインストール先の `/var/log/` に残します。

---

## 動作要件

- Arch Linux の公式 Live ISO（archiso）で起動していること
- root 権限（`sudo` または root ログイン）
- インターネット接続（有線推奨。WiFi はスクリプト内から設定できます）
- UEFI / BIOS どちらでも可（自動判別します）

必要なコマンドが不足していれば起動時に自動でインストールするため、事前準備は不要です。

| 自動導入されるパッケージ | 用途 |
|---|---|
| `gptfdisk` `parted` | パーティション操作 |
| `dosfstools` `e2fsprogs` `util-linux` | フォーマット・マウント |
| `arch-install-scripts` | `pacstrap` / `genfstab` / `arch-chroot` |
| `reflector` | ミラーサーバーの選定 |

## 使い方

Live ISO で起動し、ネットワークに接続してから実行します。

```bash
curl -fsSLO https://raw.githubusercontent.com/yannsi/esca_linux_installer/main/install.sh
sudo bash install.sh
```

`install.sh` は単一ファイルで完結しているため、USB メモリに入れて持ち込むこともできます。

```bash
sudo mount /dev/sdX1 /mnt/usb && sudo bash /mnt/usb/install.sh
```

> 公式 Live ISO は日本語フォントを含まないため、インストーラーの日本語が
> 一部「豆腐」（□）で表示されます。動作に支障はありませんが、
> 気になる場合は後述の `build-iso.sh` で日本語表示に対応した ISO を作れます。

対話に答えていくと、最後に設定内容のサマリーが表示されます。
そこで各項目を修正でき、`YES` と大文字で入力して初めてディスクへの書き込みが始まります。

### ドライラン

```bash
sudo bash install.sh --dry-run
```

ディスクへの書き込みとパッケージのインストールを一切行わず、対話の流れと生成される設定ファイルだけを確認できます。
生成物は一時ディレクトリに出力され、実行開始時にパスが表示されます。

> Live 環境の `/mnt` を汚さないよう、書き込み先を退避したうえで生成処理そのものは実行します。
> つまり「実際に何が書かれるか」を、本番と同じロジックで事前に確認できます。

### 環境変数

| 変数 | 既定値 | 用途 |
|---|---|---|
| `ESCA_DOTFILES` | （なし） | 引き継ぎ元の dotfiles ディレクトリを明示指定 |
| `ESCA_DOTFILES_REPO` | `https://github.com/yannsi/esca-dotfiles` | 取得元リポジトリ |
| `ESCA_DOTFILES_BRANCH` | `main` | 取得するブランチ |

## 選択できる項目

### パーティション構成

| 構成 | 内容 |
|---|---|
| 自動（推奨） | EFI 512M + `/`（swap なし・zram を推奨） |
| 自動 + swap | EFI 512M + swap + `/`。swap は RAM と同容量を確保し、ハイバネートに対応します |
| 手動 | `fdisk` を起動。既存の Windows を残したい場合はこちら |

ファイルシステムは **ext4 / btrfs / xfs** から選べます。btrfs を選ぶと `@`（`/`）、`@home`、`@log`（`/var/log`）、`@cache`（`/var/cache`）のサブボリュームを作成し、`compress=zstd,noatime,space_cache=v2` でマウントします。

### デスクトップ環境とディスプレイマネージャー

DE ごとに、実際に組み合わせて動くディスプレイマネージャーだけを提示します。

| デスクトップ環境 | 選べる DM |
|---|---|
| KDE Plasma | SDDM（推奨） / LightDM / greetd / なし |
| GNOME | GDM（推奨） / SDDM / なし |
| Budgie | LightDM（推奨） / GDM / SDDM / なし |
| Xfce | LightDM（推奨） / SDDM / なし |
| COSMIC | COSMIC Greeter（推奨） / SDDM / greetd / なし |
| Hyprland / Niri | greetd（推奨） / SDDM / なし |
| なし（CLI） | — |

> GNOME 49 で Xorg セッションが既定で無効になったため、GNOME に LightDM は選べません。
> こうした組み合わせは選択肢の段階で除外しています。

KDE を選んだ場合は、さらに導入規模を選べます（最小 約500MB / 標準 約1.5GB / フル 約4GB）。

### その他

- **ブートローダー**: systemd-boot（推奨） / GRUB。BIOS 環境では GRUB に自動固定されます
- **GPU ドライバー**: NVIDIA / Nouveau / AMD / Intel / 仮想環境。搭載 GPU を検出して既定値を提示します
- **WiFi バックエンド**: iwd（推奨） / wpa_supplicant / なし
- **追加パッケージ**: OpenSSH、LibreOffice、Google Chrome、yt-fzf-sh、yay、ufw、zram

## カスタム ISO の作成（build-iso.sh）

`install.sh` を組み込んだ、日本語表示に対応した独自の Live ISO を作れます。
公式 ISO には日本語フォントもコンソールの日本語表示機能も無いため、インストーラーの文字が欠けます。この ISO ならその問題が起きません。

```bash
sudo bash build-iso.sh
```

Arch Linux 上で実行してください（`archiso` が無ければ自動でインストールされます）。

| 項目 | 内容 |
|---|---|
| 必要な空き容量 | 10GB 以上（`/var/tmp` を使用） |
| 作業ディレクトリ | `/var/tmp/archiso-work` |
| 出力先 | `./out/` |
| ISO ラベル | `MYARCHINSTALL` |

作られる ISO には次の調整が入ります。

- **`install.sh` を `/root/` に配置** — 起動後すぐ `bash /root/install.sh` で始められます。ログイン時に案内も表示されます
- **kmscon を有効化** — 標準の Linux コンソールは日本語を表示できないため、tty1 の getty を止めて kmscon に置き換えています。これが日本語表示の要です
- **日本語フォントを同梱** — `noto-fonts` / `noto-fonts-cjk` / `noto-fonts-emoji` / `terminus-font`
- **`mc` を除外** — Live 環境で `Write failed` エラーの原因になるため

> 作業ディレクトリに `/tmp` ではなく `/var/tmp` を使っています。
> `/tmp` は tmpfs（RAM）なので、ISO ビルドの一時ファイルでメモリを使い果たします。

USB メモリへの書き込み例です。**書き込み先のデバイス名は必ず `lsblk` で確認してください。**

```bash
sudo dd if=out/myarchinstall-*.iso of=/dev/sdX bs=4M status=progress oflag=sync
```

## 設定の引き継ぎ

`~/.config` 以下の設定を新しい環境に持ち込めます。取得元は3つから選べます。

1. **ホストPC** — 実行中のマシンにある設定を検出して使います（既定）
2. **GitHub** — dotfiles リポジトリの最新版を取得します
3. **引き継がない** — 各パッケージの既定設定のみ

ホストPC を選んだ場合、検出できた設定の一覧が事前に表示されます。ホスト側に設定が無ければ自動で GitHub にフォールバックし、それも失敗すれば既定設定で続行します。

引き継いだ設定は、そのまま置くのではなく**新しい環境に合わせて調整**されます。

- 絶対パス（`/home/前のユーザー名/...`）を `$HOME` に書き換え
- ロック処理を WM に応じて切り替え（Niri は `swaylock`、Hyprland は `hyprlock`）
- ワークスペースモジュールを切り替え（`niri/workspaces` ↔ `hyprland/workspaces`）
- Nerd Fonts v3 で削除された符号位置のアイコンを現行のものに置換
- 実行権が落ちたスクリプトに `chmod +x` を付け直し

> 最後の項目は特に分かりにくい不具合につながります。
> Waybar の custom モジュールは、スクリプトが実行できず出力が空になると
> **モジュールごとバーから消えます**。エラーは表示されません。

## インストールの流れ

対話フェーズが終わると、以下の順で実行されます。所要時間は各ステップごとに計測され、完了時にまとめて表示されます。

1. パーティション処理
2. フォーマット & マウント
3. ミラーリスト設定（`reflector` で国内・HTTPS・24時間以内に同期されたミラーを速度順に上位8件選定）
4. ベースシステムのインストール（`pacstrap`）
5. fstab 生成
6. chroot 設定（ロケール・時刻・IME・initramfs・各種サービス）
7. ユーザー設定
8. AUR ヘルパー / Chrome / yt-fzf-sh ※選択時のみ
9. ブートローダー
10. デスクトップ環境 ※選択時のみ
11. ディスプレイマネージャー ※選択時のみ
12. 後始末（ログ保存・アンマウント）

## Esca のブランディング

デスクトップ環境を選ぶと、以下が併せて構成されます。

- **壁紙** — `esca`（配色の基準になっている画像）を DE ごとの適切な方法で既定に設定
- **SDDM テーマ「Esca」** — Qt6 対応。QtQuick のみで構成しており、Controls のスタイルプラグインが無い環境でも白画面になりません
- **専用フォント `EscaSymbols.otf`** — アンコウの誘引突起を模したグリフを **U+100000** に収録。Starship プロンプトで使います
- **`/etc/os-release`** — `NAME="Esca Linux"` として書き換え
- **初回ログインガイド** — 各ユーザーのホームに `はじめにお読みください.txt` を配置

> グリフの割り当て先を U+100000（第16面）にしているのは、Nerd Fonts v3 が
> U+E000–F8FF に加えて U+F0001–F1AF0 も使っているためです。
> 第15面までの私用領域は衝突の危険があります。

## トラブルシューティング

### 途中で失敗した

失敗したコマンド・行番号・終了コードが表示されます。

```
✘ 予期しないエラーで停止しました
  終了コード  : 1
  失敗した処理: pacstrap /mnt base sudo linux ...
  発生場所    : do_pacstrap() の 2494 行目
  ログ        : /tmp/esca-install-20260816-004512.log
```

ログは `/tmp/esca-install-*.log` にあり、インストールが完了していれば `/var/log/` にもコピーされます。

### 日本語入力が切り替わらない

`半角/全角`または`Ctrl + Space` で切り替えます。反応しない場合は一度ログアウトして再ログインしてください。IME の環境変数はセッション開始時にしか読まれません。

### 外付けディスクにインストールしたが起動しない

UEFI/BIOS で起動順序を変更する必要があります。完了画面に手順が表示されます。起動中のインストールメディア自体は、選択候補から自動で除外されます。

### アイコンが豆腐（□）になる

Nerd Font 系のパッケージが入っていない可能性があります。引き継いだ設定に Nerd Fonts v2 時代の符号位置が残っている場合は、インストーラーが自動で置換しますが、対象は Waybar の `config.jsonc` のみです。

## 開発者向けメモ

このスクリプトを触る場合、過去に踏んだ落とし穴がいくつかあります。コード中にも `【重要】` として理由付きで残してあります。

- **Nerd Font のグリフは UTF-8 バイトで直接書く。** `printf '\uf001'` はロケール依存で、Live ISO 既定の C ロケールでは文字列がそのまま出ます。`printf '\xef\x80\x81'` の形にしてください。
- **`set -E`（errtrace）は必須。** これが無いと関数内の失敗で ERR トラップが呼ばれず、原因不明のまま終了します。
- **`run_cmd_soft` は必ず `|| true` で受ける。** 失敗時に 1 を返すため、`set -e` 下で単独の文として呼ぶとインストーラごと停止します。
- **`[[ 条件 ]] && コマンド` を関数の最終文にしない。** 条件が偽のとき関数が 1 を返し、呼び出し側で `set -e` に引っかかります。
- **エラー行番号は `BASH_LINENO[0]`。** トラップ内の `$LINENO` はトラップ自身の行を指します。
- **SDDM の QML は QtQuick のみで書く。** Controls を使うとスタイルプラグインが無い環境で白画面になります。
- **`/mnt` への書き込みは必ず `run_cmd` を通す。** 直接書くとドライランのガードが効きません。
